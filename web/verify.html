VERIFY THE CODE

Dead Drop is a website, so your browser downloads the encryption code from this server on every visit. This page can compare freshly fetched responses with a manifest and helps you compare that manifest independently — while being explicit that an in-page check cannot prove the integrity of the code already executing.

1. Do fresh responses match the served manifest?

Every path listed in /SHA256SUMS is fetched again without using the HTTP cache, hashed in your browser, and compared with the manifest this origin serves. This detects drift and many deployment mistakes. It does not prove that the freshly fetched bytes are identical to the bytes already parsed or executed in this tab.

2. Does that manifest match the open-source repository?

Step 1 only shows that fresh responses agree with the manifest this same server handed you — a malicious server could serve a tampered bundle and a matching manifest and a doctored version of this very page. A separately obtained repository copy can expose that only when you reach it through a path the same adversary cannot also control. Prefer a reviewed, pinned commit or another authenticated copy you selected independently.

3. The honest ceiling

    
    
      
  • Reduce who you trust: load Dead Drop over its
        Tor onion address to remove Cloudflare from the delivery path. You
        still trust the service operator, your endpoint, and the code source you compare against.
    • 
      
  • A website can't fully win this. If your adversary is the operator (or anyone
        who can coerce them), no in-page check is enough — the page is served by the same party.
        The real fix is code that is installed once and updated through a signed, reviewed channel:
        a browser extension that pins these hashes, or a native client. That is deliberately out of
        scope for a pure website, and stated here rather than hidden.
